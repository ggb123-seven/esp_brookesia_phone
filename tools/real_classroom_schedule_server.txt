# 真实课表服务器中间层运行说明

`tools/real_classroom_schedule_server.py` 是给 ESP32-P4 教室课表 App 使用的服务器中间层。它对设备保持现有 HTTP JSON 合同，同时把 WebVPN/EAMS 登录、会话维护、页面/API 解析和缓存降级留在服务器侧。

首版 MVP 使用 Python 标准库实现，默认运行 `fixture` provider；真实学校系统接入以 `manual-session` provider 边界预留，等待人工会话材料或后续登录流程确认。

## 配置

环境变量示例：

```bash
export SCHEDULE_HOST=0.0.0.0
export SCHEDULE_PORT=8080
export SCHEDULE_API_PATH=/classroom-schedule/today
export SCHEDULE_API_TOKEN=change-me-local-only
export SCHEDULE_PROVIDER=fixture
export SCHEDULE_FIXTURE=tools/fixtures/classroom_schedule_fixture.json
export SCHEDULE_CACHE_TTL_SECONDS=600
export SCHEDULE_UPSTREAM_TIMEOUT_SECONDS=10
export PARENT_CALL_ALERT_API_PATH=/parent-call-alert/trigger
export PARENT_CALL_ALERT_API_TOKEN=change-me-local-only
export PARENT_CALL_ALERT_MODE=mock
```

不要把真实 `SCHEDULE_API_TOKEN`、学校账号、密码、Cookie、JSESSIONID 或 WebVPN 会话 URL 写入 Git。云服务器上建议把这些值放在 shell profile、systemd environment file、Docker/进程管理器 secret，或其它未提交配置中。

## 本地运行

```bash
python tools/real_classroom_schedule_server.py \
  --host 0.0.0.0 \
  --port 8080 \
  --token change-me-local-only \
  --alert-token change-me-local-only \
  --fixture tools/fixtures/classroom_schedule_fixture.json
```

健康检查：

```bash
curl http://127.0.0.1:8080/health
```

课表查询：

```bash
curl "http://127.0.0.1:8080/classroom-schedule/today?classroom=A101&date=2026-07-05&token=change-me-local-only"
```

无课样例：

```bash
curl "http://127.0.0.1:8080/classroom-schedule/today?classroom=EMPTY&date=2026-07-05&token=change-me-local-only"
```

token 错误：

```bash
curl -i "http://127.0.0.1:8080/classroom-schedule/today?classroom=A101&token=wrong"
```

家长电话告警接收接口：

```bash
curl -i -X POST "http://127.0.0.1:8080/parent-call-alert/trigger" \
  -H "Content-Type: application/json" \
  -H "X-Alert-Token: change-me-local-only" \
  --data '{"reason":"mq2_alarm","detail":"MQ-2 detected smoke or combustible gas","message":"环境监测检测到烟雾或可燃气体异常，请及时确认。","timestamp_ms":123456}'
```

告警 token 错误：

```bash
curl -i -X POST "http://127.0.0.1:8080/parent-call-alert/trigger" \
  -H "Content-Type: application/json" \
  -H "X-Alert-Token: wrong" \
  --data '{"reason":"mq2_alarm","detail":"self-test","message":"self-test","timestamp_ms":123456}'
```

## Windows 双击启动与登录自启动

Windows 本机可作为 ESP32 所在局域网内的中间层，不需要云服务器。相关脚本位于 `classroom_schedule_server_scripts/`：

- `start_classroom_schedule_server.ps1`：统一处理 Python 检查、物理网卡 IPv4 自动识别、EAMS 会话探测、浏览器会话续期、端口占用检查和服务启动。
- `start_classroom_schedule_server.bat`：桌面双击入口，不在窗口中打印 token。
- `classroom_schedule_server_config.example.bat`：不含真实凭据的配置模板。
- `set_classroom_schedule_autostart.ps1`：安装或移除 Windows 登录自启动快捷方式。
- `../tools/eams_session_refresh.py`：由启动器内部调用的可见 Edge 会话更新辅助程序，不是第二个用户入口。

会话自动更新需要 Python Playwright；浏览器使用系统已安装的 Microsoft Edge，不需要下载 Playwright 自带浏览器：

```powershell
python -m pip install playwright
```

把配置模板复制到 `.local-secrets/classroom_schedule_server_config.bat` 后填写本地值，不要把真实凭据放进启动脚本目录。配置中的 `DISPLAY_IP` 留空时，启动器会选择带默认路由的已连接物理网卡，排除隧道、VMware 和 Wi-Fi Direct 等虚拟接口。真实课表模式使用：

```bat
set "SCHEDULE_PROVIDER=eams-room-occupancy"
set "EAMS_SESSION_FILE=.local-secrets\eams-session.json"
set "EAMS_LOGIN_FILE=.local-secrets\eams-login.json"
set "EAMS_BROWSER_PROFILE=.local-secrets\eams-edge-profile"
set "EAMS_LOGIN_TIMEOUT_SECONDS=600"
set "EDGE_EXECUTABLE="
set "CHECK_EAMS_SESSION=1"
set "REFRESH_EAMS_SESSION=1"
```

双击 `start_classroom_schedule_server.bat` 即可完成一次启动流程：

1. 会话有效时直接启动服务器；已有健康实例时正常退出。
2. 会话过期时自动打开可见 Edge，并从未提交的 `eams-login.json` 填写账号密码。
3. 用户本人完成滑块并提交登录；脚本不识别、拖动或绕过验证码。
4. 登录成功后脚本自动检测 EAMS 页面，先验证候选 storage state，再原子更新正式状态文件。
5. 若旧实例确认属于当前项目，启动器安全重启该实例，使新会话立即生效；其他端口占用进程不会被终止。

浏览器默认等待 600 秒。超时、用户关闭窗口或候选会话验证失败时，旧 storage state 和旧服务器进程保持不变。Windows 登录自启动模式遇到会话过期时同样会显示 Edge 登录窗口。

只检查配置、网卡、会话和端口而不启动服务：

```bat
start_classroom_schedule_server.bat --check-only
```

`--check-only` 不打开浏览器，也不修改会话文件。启动器不会输出账号、密码、Cookie、JSESSIONID 或 API token。EAMS 返回登录页时进入一次续期流程；学校系统不可达或探测超过总时限时报告网络超时，不把两者混为一类。仅在排障时可暂时设置 `REFRESH_EAMS_SESSION=0` 禁用自动续期，或设置 `CHECK_EAMS_SESSION=0` 跳过检查后手工诊断。

安装 Windows 登录自启动，`LauncherPath` 替换为本机桌面入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File classroom_schedule_server_scripts/set_classroom_schedule_autostart.ps1 `
  -LauncherPath "$env:USERPROFILE\OneDrive\Desktop\start_classroom_schedule_server.bat"
```

自启动窗口保持最小化；启动失败时会显示诊断对话框。移除自启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File classroom_schedule_server_scripts/set_classroom_schedule_autostart.ps1 -Remove
```

第一次以 `0.0.0.0:8080` 启动时，Windows 防火墙可能询问是否允许 Python 访问网络；只需允许当前专用网络。ESP32 与电脑必须连接同一个局域网，电脑关机或休眠后设备会回退到离线缓存。

## 自测

```bash
python tools/eams_session_refresh.py --self-test
python tools/real_classroom_schedule_server.py \
  --self-test \
  --fixture tools/fixtures/classroom_schedule_fixture.json
```

自测会验证：

- fixture 能输出固件兼容 JSON。
- 楼宇/教室目录接口能返回 fixture 中的真实选项，并校验 token 与未知楼宇。
- 脱敏 EAMS HTML fixture 能解析楼宇下拉框、building id 和完整教室名，空占位与重复教室会被过滤。
- 课程按开始时间排序。
- `EMPTY` 返回空 `courses` 数组。
- 未知教室返回空课表而不是解析失败。
- 非法日期会被拒绝。
- 未知路径返回 `404 not_found`。
- `POST /parent-call-alert/trigger` 能接收固件 HTTP 告警 payload，并校验 `X-Alert-Token`。
- 告警 token 错误时返回 `401 unauthorized`，且响应不泄露真实 token。
- 告警 payload 缺少 `reason`、body 超限、非 JSON Content-Type 时会返回可诊断错误。
- 上游失败且缓存可用时返回带 `cached: true` 的缓存课表。
- `manual-session` provider 可通过假上游解析 JSON 响应和 HTML 内嵌 JSON 响应。

## 脱敏探测 WebVPN/EAMS

真实接入前，可以用 `--probe-eams` 检查本地私密配置是否已经足够访问上游。该命令只输出脱敏摘要，不打印账号、密码、Cookie、JSESSIONID、token、完整 query 或完整 HTML：

```bash
python tools/real_classroom_schedule_server.py \
  --probe-eams \
  --eams-login-file .local-secrets/eams-login.json \
  --session-file .local-secrets/eams-session.json \
  --upstream-timeout-seconds 15
```

当前已确认辽宁工程技术大学统一身份认证页面包含 CAS 字段和密码加密盐，并且对已配置账号返回 `need_captcha: true`。因此不能在服务器后台直接绕过验证码做账号密码自动登录。Windows 启动器会在会话失效时打开可见 Edge 并填写本地账号密码；用户本人完成验证码/滑块和登录提交后，启动器自动验证并更新未提交的 storage state。手工运行 `--probe-eams` 仍只负责脱敏诊断，不修改会话。

探测输出里常见状态含义：

- `login.need_captcha: true`：统一身份认证要求人工验证码/滑块。
- `session.status: placeholder_upstream_url`：`eams-session.json` 的 `upstream_url` 仍是占位文本，还没有填浏览器登录后的真实 EAMS 查询地址。
- `session.status: placeholder_headers`：`headers.Cookie` 仍是占位文本，还没有填人工导出的 Cookie。
- `session.looks_like_login: true`：会话已失效或 Cookie 不完整，上游又跳回统一认证页。
- `session.looks_like_eams: true`：会话能进入 EAMS 页面，可以继续根据 `links_sample`、`forms` 和 `interesting_lines` 定位真实教室课表查询入口。

## 真实 EAMS 教室 Provider

在用户人工通过 WebVPN/统一身份认证验证码后，可以使用 `eams-room-occupancy` provider 读取真实 EAMS 数据，并转换为固件兼容的 `courses[]`。

该 provider 当前采用两级数据源：

1. 优先读取 EAMS “全校开课查询” `stdSyllabus!search.action`，解析课程名、教师、教学班、星期、节次、周次和教室，输出与 fixture/mock 一样的课程明细字段。
2. 如果目标日期/教室在全校开课查询中没有课程明细，则降级读取 EAMS “教室资源查询”占用表，只输出占用节次；例如 `第5-7节占用`。

已验证示例：

- `尔雅103` / `2026-06-29`：可返回课程名、教师、班级明细，例如 `组织行为学`、`符萌萌`、`班级:会计25-3 会计25-4 会计25-5`。
- `尔雅103` / `2026-07-05`：教室资源表显示第 5-7 节占用，但全校开课查询无对应课程明细，且占用表单元格没有链接、tooltip 或隐藏详情字段；因此只能返回占用节次。

先用脱敏探测验证本地会话能访问 EAMS：

```bash
python tools/real_classroom_schedule_server.py \
  --probe-eams \
  --eams-login-file .local-secrets/eams-login.json \
  --session-file .local-secrets/eams-session.json \
  --upstream-timeout-seconds 15
```

再用真实 provider 拉取一次样例结果：

```bash
python tools/real_classroom_schedule_server.py \
  --probe-eams-provider \
  --eams-login-file .local-secrets/eams-login.json \
  --session-file .local-secrets/eams-session.json \
  --upstream-timeout-seconds 12
```

启动真实 EAMS provider：

```bash
python tools/real_classroom_schedule_server.py \
  --provider eams-room-occupancy \
  --session-file .local-secrets/eams-session.json \
  --token "$SCHEDULE_API_TOKEN" \
  --upstream-timeout-seconds 12
```

`eams-session.json` 仍然必须放在未提交目录。真实 provider 会从当前 EAMS 会话的标准 `class-details.action` 页面动态发现 `room.building.id`，再按所选楼宇读取完整教室名；源码和会话文件都不再需要静态楼宇 ID 映射。除 `upstream_url` 和 `headers.Cookie` 外，可保留这些非敏感配置：

```json
{
  "first_week_start": "2026-03-02",
  "semesterId": "723",
  "projectId": "1",
  "syllabus_page_size": 500
}
```

- `first_week_start`: EAMS 当前学期第 1 周周一日期，用于按查询日期计算 `iWeek`。
- `semesterId` / `semester_id`: EAMS 学期 ID，当前验证为 `723`。
- `projectId` / `project_id`: 全校开课查询项目 ID，当前验证为 `1`。
- `syllabus_page_size`: 全校开课查询分页大小；默认 `500`，用于减少分页请求次数。

## ESP32 固件配置

固件端保持当前配置方式：

- host: 云服务器公网 IP 或局域网 IP
- port: `8080`
- schedule path: `/classroom-schedule/today`
- building catalog path: `/classroom-schedule/buildings`
- room catalog path: `/classroom-schedule/rooms`
- token: 与服务器 `SCHEDULE_API_TOKEN` 一致
- parent call alert path: `/parent-call-alert/trigger`
- parent call alert token: 与服务器 `PARENT_CALL_ALERT_API_TOKEN` 一致
- parent call alert transport: 默认仍建议 `Mock/demo only`；需要联调云端接收点时再切到 `HTTP middleware`

MVP 可先用 `HTTP + IP:端口 + token` 跑通。后续有域名和证书后，再把传输层升级到 HTTPS 或反向代理。

设备打开课表 App 后先请求楼宇目录，再以 `building=<完整楼宇名>` 请求该楼宇的教室目录，最后把选中的完整教室名原样传给课表接口。三个 GET 接口共用 `token` query 参数：

```text
GET /classroom-schedule/buildings?token=<redacted>
GET /classroom-schedule/rooms?building=尔雅楼&token=<redacted>
GET /classroom-schedule/today?classroom=尔雅楼103&date=2026-07-17&token=<redacted>
```

目录请求遇到未知楼宇/教室返回 HTTP 400，会话过期返回 HTTP 503，上游解析失败返回 HTTP 502；这些情况不能伪装成成功空课表。合法但当前没有教室的楼宇返回 `rooms: []`。

## 真实 WebVPN/EAMS 接入限制

当前仓库已经确认 WebVPN/EAMS 人工会话、全校开课查询和教室资源查询链路。仍需注意以下限制：

- 统一身份认证需要验证码，当前不绕过验证码；会话仍依赖人工浏览器登录后导入 Cookie。
- 全校开课查询可以提供课程名、教师、教学班等明细，但并不覆盖所有教室占用。
- 教室资源查询可以稳定提供占用节次，但页面单元格只含节次数字，没有课程名、教师、班级、链接或隐藏详情。
- 因此某些占用可能只能显示为“第 N-M 节占用”，例如考试、临时借用、活动或非普通教学排课。

因此 `manual-session` provider 当前采用“人工会话文件导入”的安全边界：

```bash
python tools/real_classroom_schedule_server.py \
  --provider manual-session \
  --session-file /opt/classroom-schedule/eams-session.json \
  --upstream-timeout-seconds 10 \
  --token "$SCHEDULE_API_TOKEN"
```

`eams-session.json` 必须放在未提交路径中。当前支持的最小格式：

```json
{
  "upstream_url": "https://example.invalid/eams/classroom-schedule",
  "query": {
    "room": "{classroom}",
    "day": "{date}"
  },
  "headers": {
    "Cookie": "<browser-cookie-header>"
  }
}
```

- `upstream_url`: 浏览器人工登录后确认的 WebVPN/EAMS 查询地址。
- `query`: 可选查询参数模板；`{classroom}` 和 `{date}` 会替换为 ESP32 请求传入的教室和日期。
- `headers`: 可选上游请求头，通常用于人工导出的 Cookie；不要提交该文件。

上游响应支持两种最小输入：

- JSON：根对象直接包含 `classroom_name` 和 `courses`，或包在 `data` / `schedule` 对象中。
- HTML：页面内包含 `<script id="classroom-schedule-json" type="application/json">...</script>`，脚本内容为上述 JSON。

后续真实接入时建议先用浏览器人工登录 WebVPN/EAMS，导出最小必要会话材料到服务器本地配置，再根据学校页面实际结构补专用解析器，并用脱敏 fixture 固化测试样例。

## 安全与日志

- 服务启动时只打印脱敏 URL：`token=<redacted>`。
- 错误响应只返回类别和可诊断短消息。
- 不记录 query string、token、`X-Alert-Token`、Cookie、JSESSIONID、完整 WebVPN URL、完整 HTML 或完整私有课表。
- 电话告警接口只记录 `reason` 和字段长度，不记录完整 `detail` / `message` 内容。
- fixture 文件必须是人工构造或脱敏样例。
