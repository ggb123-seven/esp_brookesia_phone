# 学生指纹模板库绑定接口

## Goal

为大学生打卡系统建立“学生档案 <-> AS608 指纹模板 ID”的本地绑定接口，使指纹模块识别出的模板编号能够映射到学生姓名、班级、学号，并为后续考勤记录生成提供稳定的数据入口。

该任务是父任务 `06-19-student-checkin-terminal` 的子任务，聚焦学生身份数据层和指纹模板库关系，不直接实现完整考勤看板、天气、迟到规则或服务器同步。

## User Value

- 学生把手指放到 AS608 指纹模块后，系统不只显示模板编号，还能显示对应学生姓名、班级、学号。
- 老师或管理员可以把录入成功的指纹模板绑定到具体学生，避免模板编号和真实学生身份脱节。
- 后续考勤 App 可以用统一接口查询学生信息、生成打卡记录、判断未绑定模板和重复绑定。

## Confirmed Facts

- 父任务目标是把当前 ESP32-P4 Brookesia Phone 示例改造成本地离线优先的学生到校打卡终端。
- 当前 AS608 服务位于 `components/as608`，已有 `as608_service_enroll`、`as608_service_identify`、`as608_service_match`、`as608_service_delete_template`。
- 当前 Fingerprint App 位于 `components/apps/fingerprint`，可以录入、识别、删除 AS608 模板，并显示模板编号、得分、模块状态。
- 当前 Fingerprint App 还没有学生信息表，也没有把 AS608 `page_id` 映射到学生姓名、班级、学号。
- AS608 模板存储在指纹模块内部；ESP32 本地侧需要保存“模板 ID 到学生档案”的元数据映射。
- 项目已有 NVS、SPIFFS 初始化基础，父任务要求第一版以本地持久化为主。
- 中文 UI 文案需要使用 `fingerprint_font_20` 或后续更新后的中文字体子集，新增中文字符时要同步检查字形覆盖。
- GitHub 调研记录见 `research/github-fingerprint-attendance.md`。可直接借鉴的候选主要是 MIT 许可的 Arduino/ESP32 项目思路；当前工程仍应使用本项目已有 ESP-IDF `as608_service` 和新建本地服务组件，不直接搬运 Arduino `Adafruit_Fingerprint` 代码。
- 当前 `FingerprintApp.cpp` 将可输入模板编号限制为 `0..299`，上游 `as608_basic_high_speed_verify()` 也搜索 `0..300` 范围；第一版学生绑定接口应先沿用这个范围，后续如暴露 AS608 容量查询再抽成配置。
- 学生名单工作表应放在 SD 卡根目录 `/sdcard/students.csv`，作为老师现场维护和更新名单的优先来源；工程默认启用 SD 卡挂载能力，但挂载失败不阻断核心 App 启动，SPIFFS 中的 `students_import.csv` 只作为随固件打包的示例/兜底种子文件。
- 用户已确认 CSV 导入策略采用“替换名单但保留同学号已有模板绑定”：导入新名单时，若 `student_id` 已存在且新 CSV 没有明确指定模板 ID，继续保留原有 `fingerprint_page_id`。
- 用户要求 Fingerprint App 的录入入口面向学生姓名，而不是让老师直接管理模板库编号：应先从导入名单中选择需要录入指纹的同学，再录入并自动绑定模板 ID。
- 用户要求 Fingerprint App 初始状态不要提示“请把手指放到 AS608 指纹模块上”；只有点击“识别指纹”或开始录入流程后，才显示放置手指的提示语。
- 用户要求 Fingerprint App 主界面提供三个明确选项：`导入学生指纹`、`识别学生指纹`、`删除学生指纹`。
- 用户要求这三个入口点击后分别进入独立子页面，而不是在同一主页面上堆叠所有控件。
- 用户要求 `导入学生指纹` 流程里提供输入学生姓名的选项，输入键盘与 Setting App 联网输入密码页使用的 26 键 LVGL 键盘一致。
- 用户已确认学生姓名输入框第一版只用于筛选/定位已导入名单中的学生，不支持现场新建学生。
- 当前 Setting App 的 Wi-Fi 密码输入页已有可参考实现：`components/apps/setting/ui/screens/ui_ScreenSettingVerification.c` 使用 `lv_textarea_create()` 和 `lv_keyboard_create()`，`components/apps/setting/Setting.cpp` 中 `onKeyboardScreenSettingVerificationClickedEventCallback()` 把 keyboard 绑定到 textarea 并处理确认键。
- 当前 Fingerprint App 的 launcher 图标由 `FingerprintApp.cpp` 运行时绘制 32x32 像素数据；其他本地 App 大多使用 `components/apps/<app>/assets/img_app_*.png` 和配套生成的 LVGL `.c` 静态图标资源。
- 现有本地 App 图标风格以圆角方形彩色底、底部轻微阴影、中心白色/浅色扁平符号为主，例如 Settings、Calculator、Camera、Music Player、Video Player、2048 Game。

## Requirements

- 定义学生档案数据模型，至少包含：
  - 学号 `student_id`
  - 姓名 `name`
  - 班级 `class_name`
  - AS608 指纹模板 ID `fingerprint_page_id`
  - 绑定状态或有效标记
- 提供本地接口用于：
  - 新增学生档案。
  - 查询全部学生档案。
  - 按学号查询学生。
  - 按指纹模板 ID 查询学生。
  - 将录入成功的 AS608 模板 ID 绑定到学生。
  - 解除学生和模板 ID 的绑定。
  - 删除学生时处理对应模板绑定关系。
- 接口必须能区分以下异常情况：
  - 学号不存在。
  - 指纹模板 ID 未绑定任何学生。
  - 学号重复。
  - 指纹模板 ID 已被其他学生占用。
  - 本地存储读写失败。
- 数据需要持久化保存，断电重启后学生档案与指纹模板映射仍可恢复。
- 第一版学生名单通过 SD 卡根目录 `/sdcard/students.csv` 导入或更新；设备端主要负责浏览/选择学生并完成指纹模板绑定，不把小屏幕手动输入作为主要名单维护方式。SPIFFS 中的示例 CSV 只在没有 SD 卡名单时兜底初始化。
- 第一版按单班或小规模课程名单设计，默认目标支持 60 人，代码上预留到 128 人左右；更大规模留到后续任务评估索引、分页 UI 和存储空间。
- 第一版固定一个学生绑定一个 AS608 模板 ID；多手指/多模板属于后续扩展。
- 第一版以 `student_id` 作为设备本地唯一主键，不用 `class_name + student_id` 组合唯一；多班级复用同一设备时后续再引入命名空间或课程维度。
- 第一版 CSV 导入字段至少包含 `student_id,name,class_name`，可选包含 `fingerprint_page_id,enabled`；导入后运行时持久化文件继续保存绑定状态。
- CSV 导入按 `student_id` 合并：新名单替换学生基础信息和启用状态；同学号已有模板绑定默认保留；新 CSV 显式提供 `fingerprint_page_id` 时按导入值处理，并继续检查模板 ID 是否重复。
- Fingerprint App 后续识别成功时，应能通过该接口把模板 ID 转成学生姓名、班级、学号并展示。
- Fingerprint App 主界面应只展示三个主要操作入口：
  - `导入学生指纹`
  - `识别学生指纹`
  - `删除学生指纹`
- 三个主要操作入口点击后应分别进入独立子页面：
  - `导入学生指纹` 子页面：学生列表、姓名筛选输入、选中学生后的录入动作和录入状态。
  - `识别学生指纹` 子页面：识别动作、放置手指提示、识别结果和学生信息。
  - `删除学生指纹` 子页面：已绑定学生列表、姓名筛选、删除确认和删除结果。
- 子页面 UI 应简约、大气，使用清晰标题、充足留白、少量重点状态色和大触控目标；避免把主页面做成密集控制面板。
- 三个子页面都应提供清晰返回路径，回到 Fingerprint App 主页面后只保留状态摘要和三个入口。
- `导入学生指纹` 流程应支持从未绑定学生列表中选择学生，也支持通过学生姓名输入框筛选/定位学生。
- 学生姓名输入框第一版只筛选/定位已导入名单中的学生；如果名单里没有该学生，UI 显示“未找到学生”或同等提示，不提供现场新建学生入口。
- 学生姓名输入框应使用与 Setting App Wi-Fi 密码输入页同款的 LVGL keyboard 交互：一个 `lv_textarea` 加一个底部 26 键 `lv_keyboard`，键盘确认后回到学生选择/录入流程。
- 老师选定学生后点击录入，录入成功后自动把 AS608 返回的模板 ID 绑定到该学生。
- `识别学生指纹` 点击后才显示“请把手指放到 AS608 指纹模块上”，识别成功后显示学生姓名、班级、学号和模板 ID。
- `删除学生指纹` 流程应面向学生姓名/学号或已绑定学生列表，删除成功后同步解除学生和模板 ID 的本地绑定。
- Fingerprint App 打开后的初始状态不得在未点击识别/录入/删除前提示用户放置手指。
- 删除模板时，应同步解除本地学生档案中的模板绑定，避免残留映射。
- 删除学生档案时，第一版默认只解除本地绑定并返回原模板 ID，由调用方决定是否继续删除 AS608 模块模板；Fingerprint App 执行“删除模板”成功后，应同步按模板 ID 解除本地绑定。
- Fingerprint App launcher 图标应重构为与本地其他 App 统一的静态资产风格：新增 `components/apps/fingerprint/assets/img_app_fingerprint.png` 和配套 LVGL `.c` 资源，在 App 构造函数中通过 `LV_IMG_DECLARE(img_app_fingerprint)` 使用。
- 新图标应沿用本地 App 图标语言：圆角方形彩色背景、底部阴影/压暗边、中心高对比简化指纹符号；不再使用运行时像素绘制图标。

## Non-Goals

- 不实现完整考勤记录、迟到判断、请假状态、今日统计或班级看板。
- 不实现云端后台、服务器同步、老师 Web 管理端。
- 不实现复杂权限体系或多老师账号。
- 不把学生姓名、班级、学号写入 AS608 模块内部；AS608 只保存指纹模板，学生元数据保存在 ESP32 本地。
- 不要求第一版支持大规模数据库或复杂加密策略。

## Acceptance Criteria

- [ ] 任务设计明确 AS608 模板 ID 与学生档案的关系：AS608 保存模板，ESP32 本地保存学生元数据和绑定映射。
- [ ] 代码中存在可复用的学生指纹绑定接口，Fingerprint App 和后续考勤 App 都可以调用。
- [ ] 支持添加学生、按学号查询、按模板 ID 查询、绑定模板、解绑模板、删除学生这些基础操作。
- [ ] 重复学号、重复模板 ID、未绑定模板、存储失败等情况有明确返回值或错误处理路径。
- [ ] 学生档案和模板绑定关系可以持久化，重启后仍能查询。
- [ ] 支持从 SD 卡名单文件 `/sdcard/students.csv` 优先导入学生姓名、班级、学号；没有 SD 卡名单时可用 SPIFFS 示例名单兜底，导入后可在设备端选择学生进行指纹绑定。
- [ ] 重新导入名单时，同学号已有指纹模板绑定会被保留，除非导入文件显式改写该学生的模板 ID。
- [ ] Fingerprint App 识别成功后可以通过模板 ID 查到并显示学生姓名、班级、学号；未绑定模板时显示明确提示。
- [ ] Fingerprint App 主界面提供 `导入学生指纹`、`识别学生指纹`、`删除学生指纹` 三个主要入口。
- [ ] 三个主要入口分别进入独立子页面，子页面有清晰返回路径，不把录入、识别、删除控件全部堆在主页面。
- [ ] 子页面视觉保持简约、大气，触控目标清晰，文本不拥挤，和 1024x600 目标屏幕适配。
- [ ] `导入学生指纹` 入口显示待录入学生姓名列表，并提供学生姓名输入框用于筛选/定位学生；录入成功后把返回的模板 ID 绑定到选定学生。
- [ ] 学生姓名输入框第一版只筛选已导入名单；输入结果没有匹配学生时，提示未找到，不创建新学生档案。
- [ ] 学生姓名输入使用与 Setting App Wi-Fi 密码页一致的 LVGL 26 键 keyboard + textarea 交互。
- [ ] Fingerprint App 未开始识别、录入或删除前，不显示“请把手指放到 AS608 指纹模块上”这类操作提示；点击识别或进入录入步骤后才显示。
- [ ] 删除指纹模板或学生档案时，本地绑定关系不会留下悬空引用。
- [ ] Fingerprint App launcher 图标改为 app-local 静态 PNG/LVGL 资源，视觉风格和现有本地 App 图标一致。
- [ ] 新增中文 UI 文案时同步更新字体覆盖，避免姓名/班级相关中文显示乱码。
- [ ] `idf.py build` 通过。
