# 教室今日课程联网展示 App

## Goal

在 ESP32-P4 Function EV Board 的 Brookesia Phone 桌面中新增一个“教室课表”App，通过约定好的服务器 JSON 接口获取当前教室今天一整天的课程安排，并在设备屏幕上清晰展示每个时间段上什么课。

## User Value

- 值日、门口显示或教室终端可以直接查看当天课表，不需要打开手机或电脑。
- 当前时间段、下一节课、空闲/无课状态应能快速识别。
- 联网失败、未登录、无课表等情况应在设备上给出可理解提示。

## Confirmed Facts

- 项目是 ESP-IDF 固件项目，UI 层使用 ESP-Brookesia Phone App 和 LVGL。
- 新 App 应放在 `components/apps/<app>/`，派生 `ESP_Brookesia_PhoneApp`，实现 `init()`、`run()`、`back()`、`close()`。
- App 入口需要加入 `components/apps/apps.h` 和 `main/main.cpp`，可通过 `components/apps/Kconfig.projbuild` 配置开关控制。
- 现有 Settings App 已实现 Wi-Fi 扫描、连接、状态栏 Wi-Fi 图标和 SNTP 时间同步。
- 仓库未发现现成课程表 HTTP/API 客户端封装；课程功能需要新增一个小型联网获取/解析层。
- 中文 UI 文本必须使用包含字形的 LVGL 字体，不能依赖 Brookesia/LVGL 默认字体。
- 后台任务更新 LVGL 必须通过 `esp_lv_adapter_lock()` 保护，并在 App 关闭时停止任务。
- 凭据、密码、Cookie、Token、私有响应内容不得写入源码、Trellis 文档或日志。
- 用户提供的学校入口位于 `webvpn.lntu.edu.cn` 下，经 WebVPN 代理访问 EAMS 页面 `eams/homeExt.action`；原始 URL 带有 `jsessionid`，按敏感会话信息处理，不在文档中记录完整值。
- 用户有一台可用 Ubuntu 云服务器，因此中间接口方案具备长期运行条件；服务器可承担 WebVPN/EAMS 登录、Cookie 维护、页面/API 解析和 JSON 输出，并向 ESP32 提供稳定的课表 JSON 接口。
- 云服务器目前只有公网 IP，暂未确认域名和 HTTPS；MVP 可先用 `HTTP + 公网 IP:端口` 跑通，但 ESP32 接口需要简单访问 token，避免公开暴露课表数据。
- ESP32 端服务器 IP、端口、接口路径和访问 token 采用 `Kconfig` 编译期配置；MVP 不在 App UI 中输入或修改 token。

## Requirements

- 新增“教室课表”App，能从桌面打开、返回、关闭并再次打开。
- UI 设计阶段需要结合 UX 设计 skill 与本项目 LVGL/Brookesia 前端规范，形成明确布局、状态和交互方案后再进入实现。
- App 打开后显示加载状态，并通过后台任务从服务器接口获取当天课表。
- App 打开时自动刷新一次；页面提供手动刷新按钮；App 常开时每 10 分钟自动刷新一次。
- App 需要缓存最近一次成功获取的课表；请求失败时可显示离线缓存，并明确标注缓存状态和上次更新时间。
- 教室标识和缓存元信息保存到 NVS；最近一次成功课表 JSON 本体保存到 SPIFFS 文件，避免把较长 JSON 塞进 NVS。
- 课表按“时间段 + 课程信息”列表展示，至少包含开始时间、结束时间、课程名称。
- 如果数据中包含教室、教师、班级/节次等信息，UI 应优先展示其中对“当前教室今天上什么课”最有帮助的字段。
- App 应根据设备当前日期查询“今天”的课表；时间来源优先使用 SNTP 同步后的本地时间。
- UI 应标出当前正在进行或下一节课程；如果全天无课，显示无课状态。
- 当前教室由 ESP32 显示端在 App 内输入；MVP 输入学校系统实际需要的教室标识，App 将该标识作为请求参数发送给云服务器课表接口。
- UI 可显示服务器返回的中文教室名称，但设备端输入框不要求支持中文输入。
- App 需要将用户输入的教室保存到设备 NVS；断电重启或重新打开 App 时自动沿用上次教室，并允许修改。
- 联网、认证、解析、超时、无数据等失败场景必须显示可恢复的错误提示，并允许用户重新刷新。
- 网络请求不得阻塞 LVGL 事件回调或主 UI 线程。
- 学校账号、密码、Cookie、Token 等秘密信息只能通过本地未提交配置、NVS 或运行时输入方式保存；不得提交到 Git。
- 新增中文文案时，需要同步准备或复用有字形覆盖的中文字体，并在验收中检查字形覆盖。
- 当前任务先做 ESP32 App；服务器中间接口的真实 WebVPN/EAMS 登录、Cookie 维护和页面/API 解析暂不在本任务内实现。
- MVP 采用约定接口/模拟接口方案：ESP32 App 请求服务器提供的简化今日课表 JSON，不直接在固件内处理 WebVPN 登录和复杂网页解析。
- ESP32 端定位为课表显示客户端，负责联网请求简化 JSON、解析小体量数据、缓存/展示状态；不承担 WebVPN/EAMS 登录、Cookie 维护、HTML 解析和公网服务常驻职责。
- MVP 接口形态先按 `HTTP + 公网 IP:端口 + token` 设计，后续有域名后再升级 HTTPS。
- 服务器 IP、端口、接口路径和 token 通过 `Kconfig` 配置项提供给固件，避免在源码中硬编码。

## Acceptance Criteria

- [ ] 固件中出现一个可打开的“教室课表”App。
- [ ] 规划阶段产出 UI 设计方案，覆盖首页、教室输入/修改、加载、课表列表、无课、错误、刷新等状态。
- [ ] App 提供教室输入能力，并使用输入的教室查询当天课表。
- [ ] App 能保存教室到 NVS，重启/重开后自动加载并查询该教室。
- [ ] Wi-Fi 已连接且云服务器课表接口可访问时，App 能获取并显示当天课程时间段和课程名称。
- [ ] App 打开自动刷新，点击刷新按钮可重新获取，常开时约每 10 分钟自动刷新。
- [ ] 请求失败且存在缓存时，App 显示最近一次成功课表，并标注“离线缓存/上次更新”；无缓存时显示错误提示。
- [ ] 最近一次成功课表 JSON 保存到 SPIFFS，重启后网络失败时仍可读取并显示缓存。
- [ ] ESP32 请求云服务器接口时携带访问 token；源码和日志不泄露 token。
- [ ] 当前课程或下一节课程在 UI 中有明显状态。
- [ ] 无课、未联网、认证失败、请求超时、解析失败时，App 显示明确中文提示且不崩溃。
- [ ] 关闭 App 时后台联网/刷新任务停止，不再访问已释放的 LVGL 对象。
- [ ] 源码、日志、Trellis 文档中不包含学校账号密码、Token、Cookie 等秘密。
- [ ] `idf.py build` 通过。
- [ ] 在硬件上验证 App 打开、刷新、返回、关闭、重新打开流程。

## Out Of Scope For MVP

- 多教室切换和复杂排课管理。
- 离线编辑课表。
- 后台常驻通知或跨 App 弹窗。
- 直接在设备上完整维护学校账号资料，除非后续确认必须这么做。
- 云服务器端真实抓取学校 WebVPN/EAMS 课表、账号登录、Cookie 刷新和 HTML/API 解析。
- 域名、HTTPS 和证书部署。

## Open Questions

- 学校系统返回的数据字段、日期格式、课程时间格式和认证机制是什么？
- WebVPN 与 EAMS 的认证方式需要确认：是否能用学校统一账号密码直接登录，还是必须先在浏览器中获得 Cookie/JSESSIONID 后再访问。
- 后续可考虑把服务器配置迁移到 NVS 设置页，但不属于 MVP。
