# 修复课表读取与楼宇中文显示

## 目标

恢复 ESP32 教室课表 App 到 Windows 局域网课表服务的完整读取链路，并确保楼宇选择主控件及弹出列表正确显示中文。

## 已确认事实

- Wi-Fi 蓝屏与自动重连已经修复，并已由用户在设备上确认正常。
- 本机 WLAN IPv4 当前为 `10.96.111.246`，课表服务预期监听 `0.0.0.0:8080`。
- 当前固件 `sdkconfig` 中课表服务器 host 仍为旧地址 `10.34.88.246`；设备 NVS 还可能保存另一地址，必须结合 COM3 日志确认实际请求目标。
- 固件与 Windows 服务的端口、API path 和 token 当前一致；检查过程不得输出 token 原文。
- Windows 已存在允许 `python.exe` 入站的防火墙规则，但当前 `8080` 没有监听进程。
- 固件请求合同为 `GET /classroom-schedule/today?classroom=<教室>&date=YYYY-MM-DD&token=<token>`，成功响应必须包含匹配的 `date`、`classroom` 和 `courses` 数组。
- 真实 EAMS 教室占用页列出 13 个可查询地点及 building id：博文楼 7、知行楼 8、主楼机房 9、静远楼 11、博雅楼 13、耘慧楼 14、物理实验室 15、葫芦岛物理实验室 16、中和楼 17、致远楼 18、新华楼 19、尔雅楼 20、葫芦岛机房 21。
- `classroom_schedule_font_20.c` 已包含当前学期课程语料字形，但楼宇列表与 dropdown 箭头仍需单独做覆盖检查。
- dropdown 主控件和创建时取得的弹出列表目前都设置了本地中文字体，但仍需处理打开/重建或状态样式覆盖场景。
- App 已把 `_selected_date` 复制到请求快照，服务端也按 `date` 查询并原样返回响应日期；需要用日志验证设备运行时三者一致。
- 当前 fixture 只包含 `A101/B202`，而固件第一版只允许“尔雅楼 + 房间号”，所以 fixture 会对设备的合法教室请求返回空课程；这是“修改日期后仍无课程”的直接测试数据根因。
- `.codex/config.toml` 是用户本地修改，不属于本任务，不能提交。
- 用户已明确取消本阶段及既有提交的 GitHub 推送。

## 需求

- fixture 课表仅用于验证接口和固件显示链路，不得作为真实课表验收结果。
- 必须先在电脑端取得并可视化真实 WebVPN/EAMS 课表，由用户核对教室、日期、节次和课程内容；用户确认正确后才继续设备端验收。
- 启动并验证 Windows 局域网课表服务监听 `0.0.0.0:8080`，确认本机 `/health` 和设备将请求的教室/日期接口可用。
- 抓取打开课表 App 时的 COM3 日志，确认设备已获得 STA IP，并记录实际请求 host、port、path、教室、日期、HTTP 状态和解析结果；日志不得包含 token。
- 定位并修复 HTTP、JSON、缓存或配置错误，使当前教室和日期查询能显示服务端返回的课表或明确的无课状态。
- 保证界面选中日期、HTTP 请求日期和响应日期一致；不一致时拒绝展示并给出明确日志。
- fixture 必须至少包含一个固件可实际选择的“尔雅楼”教室及课程，避免联调永远落入空课表。
- 对旧 PC 地址或 NVS 保存地址导致的失败给出可操作诊断，避免只显示笼统“无法获取课表”。
- 楼宇 dropdown 必须列出真实 EAMS 页面提供的全部 13 个地点，服务器必须能把每个地点映射到对应 building id。
- 楼宇 dropdown 的主控件、弹出列表、选中项和打开状态必须显式使用 `classroom_schedule_font_20`；右侧 `LV_SYMBOL_DOWN` 必须使用包含该符号的 LVGL 字体，不能显示为缺字方框。
- 字体覆盖检查必须包含源码 UI 文案、楼宇名称和 mock/fixture 返回的中文字符，缺字数为 0。
- 修改后执行 `idf.py build`，然后刷写 COM3。
- 刷写后由用户验证课表读取和楼宇显示；用户确认前不提交本任务代码。
